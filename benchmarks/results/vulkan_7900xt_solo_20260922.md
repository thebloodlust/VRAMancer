# D3.d (moitié AMD) — RX 7900 XT seule, llama.cpp Vulkan/RADV

> Mesuré le 2026-09-22 dans la VM QEMU (passthrough VFIO). **Chiffres bruts, copiés
> de la sortie de `llama-bench`.** Aucune extrapolation.
>
> **Ce rapport ne répond PAS à D3.d.** D3.d demande la paire mixte NVIDIA+AMD ; la
> RTX 3090 est inutilisable aujourd'hui (aucun module noyau nvidia pour le kernel
> 6.8.0-139, voir `conclusion7900xt.md`). Seule la moitié AMD a pu être mesurée.

## Configuration

| Élément | Valeur |
|---|---|
| GPU | AMD Radeon RX 7900 XT (RADV NAVI31), 20 464 MiB, passthrough VFIO |
| Build | llama.cpp `b49650adb` (b11026), backend Vulkan précompilé |
| Modèle | Qwen3.6-35B-A3B UD-Q4_K_M — 20.60 GiB, 34.66 B params, **40 couches**, MoE 256 experts (8 actifs) |
| Bench | `llama-bench -p 512 -n 128 -fa on -dev Vulkan0`, `-r 2` (sauf CPU : `-r 1`) |
| Hôte | 172 GB RAM, kernel 6.8.0-139, `amdgpu.runpm=0 amdgpu.aspm=0` |

## Résultat principal : le nombre de couches offloadées n'est PAS monotone

| `-ngl` (couches sur GPU / 40) | pp512 (tok/s) | tg128 (tok/s) |
|---|---|---|
| 0 (CPU seul, contrôle) | 115.37 | 6.59 |
| 30 | 321.48 ± 6.84 | 21.04 ± 0.15 |
| 34 | 460.82 ± 21.32 | 25.52 ± 3.16 |
| **38** | **829.14 ± 24.55** | **37.78 ± 0.27** |
| 40 (toutes les couches) — run 1 | 128.65 ± 0.14 | 17.43 ± 0.14 |
| 40 (toutes les couches) — run 2 | 120.15 ± 0.29 | 8.95 ± 2.42 |

Sondages complémentaires (`-p 0 -n 32`, `-r 1`) : `-ngl` 42/44/46/48 sont clampés à 40
couches et donnent tg32 = 13.51 / 13.36 / 10.66 / 13.51 — même régime dégradé.

**Lecture honnête.** Le modèle fait 20.60 GiB pour 20.0 GiB de VRAM utilisable. À
`-ngl 38`, deux couches restent au CPU et **tout tient** : 37.78 tok/s en génération.
À `-ngl 40`, on demande 0.6 GiB de trop : le pilote déborde en mémoire hôte et le débit
s'effondre à 8.95–17.43 tok/s, **avec une variance énorme entre deux runs identiques**
(instabilité typique d'un spill). Mettre « tout sur le GPU » coûte ici **2 à 4× le débit**.

Ce n'est pas une découverte sur VRAMancer : c'est llama.cpp qui fait le travail, et
n'importe qui réglant `-ngl` à la main trouverait pareil. C'est en revanche exactement
le type de réglage que l'orchestrateur doit choisir automatiquement, et la mesure donne
le critère : **s'arrêter juste en dessous de la saturation VRAM, pas à 100%**.
